# Deploying: API on Render, UI on Streamlit Community Cloud

Two separate deployments. The UI never runs the backend; it calls the API over HTTPS from Streamlit's server (so **no CORS
configuration is needed**: the browser never calls the API).

| Part | Host | Entry point | Dependencies | Branch |
|---|---|---|---|---|
| Backend (FastAPI, SQLite tools, ChromaDB RAG, LangGraph) | Render web service | `uvicorn api.main:app` (after `scripts/bootstrap_deploy.py`) | `requirements-api.txt` | `deploy/render` |
| UI (Streamlit) | Streamlit Community Cloud | `ui/app.py` | `ui/requirements.txt` (streamlit, requests) | `deploy/render` |

## 1. Backend on Render

1. Render dashboard -> **New** -> **Blueprint** -> connect `tarunyadav13/CodeForge` -> choose branch **`deploy/render`**. Render reads
   `render.yaml`. (Manual alternative: **New -> Web Service**, same repo/branch, Runtime *Python*, and enter the values below.)
2. Values in `render.yaml` (shown so a manual setup matches):
   * **Build command:** `pip install --upgrade pip && pip install -r requirements-api.txt`
   * **Start command:** `python scripts/bootstrap_deploy.py && uvicorn api.main:app --host 0.0.0.0 --port $PORT --workers 1`
   * **Health check path:** `/health`
   * **Plan:** `standard` (not free, see "Memory"). **Disk:** 2 GB mounted at `/var/data`.
   * **Environment:** `PYTHON_VERSION=3.13.1`, `STUDENT_DB_PATH=/var/data/student_services.db`, `CHROMA_DIR=/var/data/chroma`,
     `HF_HOME=/var/data/huggingface`, `OPENAI_MODEL=gpt-6-luna`, `AUDIT_ADMIN_TOKEN` (generated by Render).
3. When prompted, set **`OPENAI_API_KEY`** (optional, secret, entered only in the Render dashboard). Leave it empty to run without an
   LLM: answers then quote the cited text and say so; `/health` shows `llm: not_configured`.
4. Apply. The first start downloads the embedding model (~90 MB, needs outbound internet) and builds the database and index; allow a
   few minutes. Then open `https://<your-service>.onrender.com/health`: expect `sqlite: ok (36 students loaded)` and
   `vector_store: ok (15 chunks, 6 sources)`.

Keep **one instance and one Uvicorn worker**: the source-register lock is per process.

## 2. UI on Streamlit Community Cloud

1. share.streamlit.io -> **New app** -> repository `tarunyadav13/CodeForge`, branch **`deploy/render`**, main file **`ui/app.py`**.
2. **Advanced settings -> Secrets**, paste (the URL is your Render service URL, `https://`, no trailing slash, no path):

   ```toml
   API_BASE_URL = "https://<your-service>.onrender.com"
   ```

   **The variable to set is `API_BASE_URL`.** The UI reads the Streamlit secret first, then the environment variable (Streamlit
   exports top-level secrets as environment variables), and has **no default**: if neither is set it shows how to configure it and
   makes no request. The sidebar "API base URL" box overrides it for the session.
3. Deploy, then check the sidebar "System status" and ask a question. Changing the secret needs an app reboot.

Local development is unchanged except the URL is now explicit: `$env:API_BASE_URL = "http://127.0.0.1:8000"`.

## 3. What persists (Render)

| Data | Where | Survives restart / redeploy? |
|---|---|---|
| SQLite (students, rules, Source Register, **audit records**) | `/var/data/student_services.db` on the disk | **Yes**, while the disk exists (disk is a documented Render feature of paid services; not verified by me on Render) |
| ChromaDB index + `source_register.json` | `/var/data/chroma` | **Yes**, same condition |
| Embedding model cache | `/var/data/huggingface` | Yes (otherwise re-downloaded on every start) |
| Uploaded originals | `data/uploads/` in the app directory | **No** (not needed for retrieval; the chunks live in ChromaDB) |
| Everything on a **free** instance | ephemeral | **No**: rebuilt by `bootstrap_deploy.py` from the repository on each start; documents ingested via `/ingest` and audit records would be lost |

`bootstrap_deploy.py` is idempotent: with a persistent disk a restart finds everything present and does no work (4 s locally).
It loads only the **synthetic** students and the documents in `data/source_register.csv` that have an `effective_from`; the three real PDFs
are skipped because their dates are unknown. A corpus failure (for example no internet for the model) does not stop the API; use
`--strict` to make it fatal.

## 4. Memory (why not the free plan)

Measured locally on Windows with the production start sequence: API process tree **145 MB at start, 629 MB after the first question
(embedding model loaded), stable over 6 questions.** That exceeds a 512 MB limit. The blueprint therefore uses `standard`
(2 GB RAM per Render's pricing page when written; confirm current plans and price yourself, this is a paid plan). Linux memory may differ
somewhat from the Windows figure. A free-tier deployment would need a smaller embedding setup, which is not implemented.

## 5. Security notes

* Secrets (`OPENAI_API_KEY`, `AUDIT_ADMIN_TOKEN`) live only in the Render dashboard; `render.yaml` has none (a test checks this).
* **The "login" is the `X-Student-Id` header** (a prototype identity, labelled as such in the UI). Anyone who can reach the public API
  URL can send any student ID. The data is synthetic; do not put real student data on this deployment. Isolation between students
  inside the API (refusing other students' IDs, tools locked to the header identity, no question text in audit logs) is unchanged.
* `/audit/{trace_id}` for a student's record needs that student's header or `X-Admin-Token`.
* Do not enable `--reload` or more than one worker in production.

## 6. Verified vs not verified

**Verified locally (this machine):** the exact start sequence (`bootstrap_deploy.py`, then Uvicorn with `--workers 1`) on empty storage;
bootstrap idempotence; `/health` and a cited `/ask` answer without an LLM key; the memory figures above; 19 offline tests in
`tests/test_deploy_config.py` (URL resolution incl. the Streamlit secret, requirements cover every backend import, blueprint
contents, bootstrap behaviour); the full offline suite.

**Not verified:** anything on Render or Streamlit Community Cloud (no account access from here): that Render accepts Python 3.13.1 and
this blueprint, the disk mount, the real memory on Linux, build time, cold-start time, that Streamlit Cloud picks
`ui/requirements.txt`, HTTPS between the two. Treat the first deploy as the test, and check the Render logs and `/health`.
